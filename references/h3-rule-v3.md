# H3 关键设计取舍 · 第三轮候选规则

读取完整原题。评审先写出一项满足全文的简单实现，再从题面提取仍留给实现者的决定。仅用原文、它允许的输入及普通工程推论；回放环境缺源码时标记该限制。输出准入、待核、换位和一句可复核的理由。

**一、逐项判断作用域。** 把决策单位写清楚，如一笔订单、一个文件、一次授权、一套客户端策略。标明作用阶段，如运行中、提交时或批次完成后。分清同一对象必须唯一和整批必须同时生效。先检验主工作与强制条款，再检验候选方案和示例。同一个范围内互相冲突的要求不能同时作为两条合法路径的依据。

**二、业务口径。** 同一笔输入、同一次实际业务操作，至少有两种合法处理。明确两种选择分别保护的业务目的、谁会使用结果，以及金额、归属、可用范围、结算或恢复动作的差异。数字、状态或日志有别时，沿原文再找一步，核对消费者会用该差异处理什么。验收只要求显示这项中间差异时，保留为待核。

**三、工程责任。** 成功值可以相同。核对两种设计在正常使用、并发、失败、撤销、重放或新旧版本交接期间，谁保证正确。需要指出实际入口与消费者、两种保证位置或时点、能发现漏掉该保证的操作。按原文可以推演架构选择，题面无须列出选项或强制写“由你设计”。审计状态、结束时间或资源占用变化时，继续查明它是否改变下一笔合法操作或能阻止哪种实际错误；仅提前在审计上标完、随后补一行轨迹，推不出运行责任已改变。

**四、一个决定被锁定后检查其他轴。** 若题面明确交给实现方另一项设计，使用同一份题面允许的最小输入测试，例如恰在两个窗口交点的一笔记录、升级前已经生成的一批数据。无需证明这个合法输入已经在历史上发生。通用数学边界仍需连接实际分组或消费结果；兼容设计仍需说明旧数据如何进入真实读取或恢复入口，以及两种设计各自的责任。字段优先级、调参、兼容口号不能单独放行。

**五、反证与结论。** 删除评审自行添入的业务时限、提前下载用途、跨租户资格、无损转换承诺、补发申请和重试资格。若仍存在一条满足业务口径或工程责任的轴，给出准入、原文和检验方法。资格或后果缺证记待核；所有可见轴均已规定或第二支违反同范围硬约束记换位。待核在首轮指标中按拦截计算。平台回执即使接受了和主需求矛盾的选项，也保留分歧。
