# 结构化困难设计（H1/H2/H3）

本规则处理 2026-11-15 `dfzr10007` 批次的真实判废：13 条题面在本地用同一条
`难度复核` 备注通过，提交后被平台按 P4/P5 判为难度不足并直接废弃。备注不是题面，
平台只判最终题面的真实任务，因此从本版起：

- `难度复核` 备注不再能放行 G16/G19。
- 每个 `task_plan[]` 必须先写 `difficulty_design`，再写最终提示词。
- 缺少、空泛、无法回查或只靠列表/详情/概览一致撑起的困难设计，写表和交接都直接拒绝。

共同根因不是题面“词不够多”，而是：

1. 只在一行/一页/一个台账内做一致性和状态处理；
2. 第二业务面只是展示或下载，没有真的消费、写入或持久化数据产物；
3. 题面提前规定实现顺序，设计者没有需要权衡的判断；
4. 通用 `难度复核` 备注与实际题面脱节。

## 硬约束

- `difficulty_contract_version` 必须为 `1`，每个 plan 的 `difficulty_design.version` 必须为 `1`。
- `reasoning_challenge.constraints` 至少两条，`kind` 至少两种不同值；每条都写 `failure_if_omitted`。
- `module_integration.secondary_modules` 至少一个，`role` 必须是消费、写入、下游、审计、持久化、编排、通知或授权角色；列表/详情/概览等纯展示角色不允许。
- `design_tradeoff.options` 至少两个，`implementation_not_prescribed` 必须为 `true`，题面摘录必须写出取舍轴或结果不变量。
- `hard_evidence` 至少一项，必须来自统一 G16 判据的硬证据组。
- `module_anchors` 至少两条，跨两个模块、两个不同源码路径，且原文和行号可回查。
- 三段 `prompt_excerpt` 必须逐字出现在最终题面；`data_artifact` 必须出现在第二模块的题目摘录中。
- `anti_patterns` 七项必须全部为 `false`；任一项为 `true` 说明题面仍是平台已判废的中等模板。
- 题面若连续使用四个以上“先/再/然后/逐项/依次”等过程词，而设计取舍摘录没有开放判断或结果不变量，直接拒绝。

## 自检顺序

1. 先生成 H1/H2/H3 设计，不从最终题面倒填。
2. 用真实源码抄两条锚点，确认它们不是同一个模块的两个视图。
3. 写题面时只固定输入、输出、失败后果和兼容边界，不固定内部算法、批次实现、页序或字段名，除非它们是真实既有契约。
4. 跑 `check_difficulty_contract.py`，再跑 G16/G19、领域和写表闸。
5. 如果 G16/G19 命中，必须换主任务或题位重出；不能补备注、加形容词或只换同义词。
6. 将本批 13 条的判废形状作为反例自查：若新题仍能概括成“单页状态/列表/导出一致 + 过程步骤已给定”，直接淘汰。
